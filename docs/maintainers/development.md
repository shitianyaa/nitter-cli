# 开发指南

本页是维护者的开发流程。公开 CLI 与 SDK 文档位于 `docs/{en,zh-CN}/`。

## 环境与快速验证

- 使用 `go.mod` 声明的 Go 版本（当前 1.27.0）。默认离线验证不需要任何真实
  实例或凭据。

```bash
go test ./...          # 全部单元测试（离线）
go vet ./...
gofmt -l .             # 必须为空
sh scripts/build.sh    # 产出 ./nitter（VERSION=可覆盖，默认 dev）
```

- `go test -race ./...` 由 CI 执行（ci.yml）；本地 `go test -race` 不可用时，
  以 CI 结果为准。Windows 开发机上 `CGO_ENABLED=0` 且通常没有 gcc，本地
  **跑不了** `-race`，所以这一项无法本地替代——不要因此把 CI 挪到只在合并后跑，
  否则竞态只能在上 main 之后才被发现。本地能完整替代的是上一条命令组：
  `go test ./...`、`go vet`、`gofmt -l`、`sh scripts/build.sh`，以及在 Git Bash
  下跑 `sh e2e/run.sh`（POSIX 权限断言在 MINGW64 上会自动 skip）。
- 若安装了 `pre-commit`，交付前运行 `pre-commit run --all-files`。仓库钩子：
  `gofmt -l` 必须为空 + `go test ./...`。
- 手工冒烟（离线安全）：`./nitter --version`、`./nitter <cmd> --help`、
  `nitter config path/get/set` 往返、`nitter watch --once`（无实例时应以
  退出码 1 报每源失败而非崩溃）、`nitter seen list`（空库打印 `(empty)`）。

### CI 触发范围（不必为纯文档改动担心）

`ci.yml` 只在 `pull_request`（限 `main`）与手动 dispatch 时运行；`main` 本身没有任何
push 触发的 workflow——所有变更经 PR 进入并过门。具体跑哪些检查由
`scripts/classify-change-scope.sh` 依据 `.github/ci-change-scope.gitignore` 对
**聚合 diff** 分档决定：

- **纯文档改动**（`docs/**`、`changelog/**`、`skills/**`、`.agents/skills/**`、
  `README*`/`AGENTS.md`/`CONTRIBUTING*`、`.gitignore`、`.gitattributes`、
  `.pre-commit-config.yaml`）：`Quality gate` 与 `Windows parity` 整体 skipped，
  但 check 名仍然存在，分支保护的 required checks 保持稳定。
- **质量档**（`.github/workflows/**`、`tools/**`、`scripts/classify-change-scope.sh`、
  PR 模板、labeler）：只跑 `Quality gate`，不跑 Windows parity。
- **其余任何路径**（Go 代码、`go.mod`、`e2e/**`、`scripts/build.sh`、`LICENSE`）：
  质量门 + Windows parity 全量跑。这是刻意的：EOL 与 ignore 规则的错误会真实
  影响构建产物。

分类器在 `scope` job 里从 **base 提交** checkout 运行，PR 无法通过修改规则文件或
脚本改写评判自己的标准；空 diff、无 base 等异常一律退回全量验证。一个 PR 里混进
一个非文档文件（哪怕某个 commit 本身是纯文档）就会升级为全量。

与 CI 并行的 PR 门禁见 `.github/workflows/pr-metadata.yml`（模板三段 + 清单勾选，
发布 `PR template gate` / `PR commands gate` 两个稳定 status）与
`.github/workflows/pr-triage.yml`（路径标签、指派）。

```text

changelog/unreleased/        # 双语发布说明草稿区
```

## 测试布局

- 每包邻接 `*_test.go`；外部测试包（`package x_test`）优先；解析器用
  `testdata/*.html|*.xml` fixture。
- `sdk/models_test.go` 用 golden JSON 钉死 NDJSON 数据契约（注意：必须走 jsonx
  语义 `SetEscapeHTML(false)`，裸 `json.Marshal` 会把 `&` 转义成 `\u0026`）。
- `internal/watch` 的选推逻辑（首跑/上限裁剪/水位推进/失败不落盘）表驱动全覆盖。
- 任何新增 flag/输出语义都要同步扩展对应命令的 usage-error 测试（退出码 2）。

## 提交规范

- Conventional Commits，单行英文小写 subject（`feat(cli): ...`、
  `fix(watch): ...`）。
- 不添加 AI 署名、AI 相关 Co-Authored-By 尾注或「Generated by AI」字样。
- 文档义务（AGENTS.md 变更路由）：CLI 行为/flag/输出语义变更必须同步
  `docs/{en,zh-CN}/cli-reference.md`、双语 README、`skills/nitter-cli/` 与
  `changelog/`；SDK/模型签名变更同步 `docs/{en,zh-CN}/sdk.md` 与
  `docs/maintainers/architecture.md`。完整路由表见
  [`agents/documentation-guidelines.md`](agents/documentation-guidelines.md)。

## Changelog 约定

- `changelog/unreleased/{en,zh-CN}.md` 是可选人工草稿区，发布 workflow 不读取。
- 每次发布前把定稿的双语条目移入目标 `changelog/vX.Y.Z/` 目录（英文在前、
  简体中文在后，GitHub Release 正文同时呈现两语），并同步 `changelog/README.md`
  的版本入口表（含 compare 链接）。
- 条目按用户可见结果分组（Added/Changed/...），空的标准小节省略；格式遵循
  Keep a Changelog 1.1.0 + Semantic Versioning。
- 发布后 `skills/nitter-cli/SKILL.md` 的 `version` 字段必须与 tag 版本一致。
- 发布流程细节见 [`.agents/skills/nitter-cli-release-notes/`](../../.agents/skills/nitter-cli-release-notes/SKILL.md)。

## 发布流程（骨架）

发布自动化由 `.github/workflows/release.yml` 承担：

1. **tag 触发**：软校验目标 `changelog/vX.Y.Z/` 双语条目齐全（缺失时仅发出
   warning，不阻断构建）。
2. **构建矩阵**：6 平台（macos-15-intel / macos-15 / ubuntu-24.04 /
   ubuntu-24.04-arm / windows-2025 / windows-11-arm），`CGO_ENABLED=0`，
   产物为 tar.gz（unix）/ zip（windows）压缩包，附 `VERSION` linker 注入与
   合并后的 `checksums.txt`。
3. **GitHub Release 草稿**：workflow 以 `--generate-notes` 创建草稿并上传
   全部压缩包与 `checksums.txt`；发布前由维护者把 `changelog/vX.Y.Z/` 的
   双语说明填入草稿正文。
4. 发布前人工核对：`nitter --version` 输出新版本号；skill
   `skills/nitter-cli/SKILL.md` 的 `version` 字段与 release 版本对齐。

## 质量门清单（交付前）

- [ ] `go test ./...` 全绿
- [ ] `gofmt -l .` 为空；`go vet ./...` 干净
- [ ] `sh scripts/build.sh` 成功，`./nitter --version` 正常
- [ ] 受影响命令的 `--help` 实测与文档一致
- [ ] 改动涉及 `e2e/` 覆盖的契约时，`bash e2e/run.sh` 通过
- [ ] 文档路由完成（cli-reference / README / skill / changelog，按 `agents/documentation-guidelines.md`）
- [ ] 提交信息符合 Conventional Commits 单行英文小写
- [ ] 未包含凭据、本地状态或构建/测试产物（`Progress/`、`Testignore/`、`nitter.exe` 均已在 `.gitignore`）
